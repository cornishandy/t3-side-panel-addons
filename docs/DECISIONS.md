# Decisions

- **18 Oct 2026 — keep patches alive with a keeper, not by hand.** Each nightly update wiped hand patches (three on 18 Oct). The keeper patches only a build a running T3 already has open, because changing a build before its first launch makes Gatekeeper call it "damaged". It swaps in a patched clone atomically and live-writes the UI files, so Shift-Cmd-R shows changes.
- **18 Oct — match by stable markers, never minified names,** so units survive new builds; a unit that can't match is skipped with a notification.
- **19 Oct — add-ons served by an always-on, Mac-only loopback server** (approved: "Yes, Mac-only"). T3's renderer has a header CSP that blocks remote `<script src>`, so a 628-byte inline loader fetches the code and inlines it. Every endpoint requires Origin `t3code://app`.
- **19 Oct — every add-on gets its own switch** in the ✦ panel, so any one can be undone.
- **19 Oct — firstClick unit:** the first click on an inactive T3 window should open the thread under it (Electron `acceptFirstMouse`).
- **20 Oct — usage reads are read-only:** T3's IndexedDB is opened read-only and closed at once; `lab-usage --json --read-only` takes no lock and writes nothing.
- **24 Oct — font names belong in the ✦ panel, not the main chat screen** ("TOO prominent").
- **25 Oct — only T3's native thread list:** the Group / Sort / Native views bar was removed (code kept, not installed). Compact threads added, on by default, with a switch.
- **25 Oct — sidebar sections (layout A, titles style 1, picked from mockups):** pinned threads get a quiet label and a hairline; active threads idle well past the newest few (within 3 h of the newest, then on through gaps under 2 h; the newest 3 always stay) fold under one "Show N older" row placed above them so it never moves; ages come from T3's own row age. Any Shift/Cmd/Ctrl selection shows every older thread until a plain click or Escape, since T3 selects across hidden rows. One-row titles end in "…" but repeat a trailing (N)/(Model). Reviewed by GPT-6-Astra (design) and GPT-6.1-Sol (code).
- **31 Oct — the Older section folds by a set age, default 2 days** (Andy: "make a group/section in side-panel for anything older than... and have that be in the options. default to 48 hours (2 days)"). The "Show N older" row became a header shaped like T3's own shelf headers ("Older than 2 days", count, chevron), which keeps its name when open. Choices: 12 hours, 1 day, 2 days, 3 days, 1 week, and Auto (the 25 Oct by-gaps rule, kept so it isn't lost). A set age shows the section even for one thread. Setting key `olderAfter`.
- **25 Oct — gaps by time (option D, consensus of Astra, Sol and Gemini; Grok preferred gaps only at standing-out pauses):** no lines between rows; a 10 px gap before an active row last active 25+ min after the one above, using T3's own age time (last user message, else thread update) from the service's new `ageAt`; never across Pinned, Working or the fold row; unknown times draw no gap. The ✦ Settings show/hide is now remembered.
- **25 Oct — geminiQuota unit:** T3's Antigravity limits probe sends a User-Agent version for which Google omits the Gemini buckets; the unit sends `2.24.0`. Upstream: pingdotgg/t3code#22876.
- **25 Oct — published as its own public repo** after a privacy pass: home paths and the Mac's tailnet name replaced, iCloud conflict copies and test screenshots left out, gitleaks clean.
- **25 Oct — compact sidebar usage in a short window:** the four-lab block took too much room when the window was squished vertically. Under 800 px tall it becomes one line per lab (on by default, with its own switch).
- **25 Oct — find fonts on screen (all three mockups combined, "love all three, combine in smart clever way, don't just append"):** Andy usually has the section he wants to change on screen but couldn't tell which font option controls it. One inspector: hover names the area (option A's tag), holding Shift labels every area (option C), a click opens the Fonts dialog docked beside the text, non-modal, so changes show live (option B), and Show on screen goes the other way. Ownership is read from the live CSS by probing the add-on's own `<html>` attributes, naming an area only when that one area changes the text (Astra's pre-OK). Four switches. Reviewed by GPT-6-Astra (pre-OK, three final rounds) and GPT-6.1-Sol; their reproductions are the `font-picker-*` tests.
- **25–26 Oct — installable by other T3 users** (Andy: "goal is to make this publicly available, can you do that? consider sec/priv prot"; picked "Installable by others" and "Leave history"). Parts tied to the author's own tools (`lab-usage`, `handover`) switch off cleanly when missing; new installs leave the author's title rules (rule, fit, titleGuide) and restart reminders off; Node is found anywhere (22.16+ or 24+, probed for `node:sqlite`). A "Personal experiment" note heads every README (Andy, 25 Oct: "note everywhere that I'm just using this for my personal items").
- **26 Oct — signed add-on code, single-user Mac** (Andy picked "Sign code, single-user Mac" over full pairing). GPT-6-Astra found that the loader ran whatever answered on port 8793, so another account could inject code while the service was down. The loader now runs the add-ons only when their ECDSA P-256 signature matches the key baked in at patch time. Other accounts on the same Mac can still read or fake the add-ons' data (usage, thread IDs and titles); SECURITY.md says so plainly, and the ✦ switches give no confidentiality. A per-connection account check was dropped: netstat's pid isn't a socket credential (Astra). Plan by Astra (3 rounds), built by Grok 4.7, reviewed by GPT-6.1-Sol, final OK by Astra.
- **26 Oct — Questions and Reasoning without the native bridge** (Andy: "it loads, but fonts don't actually apply"; then "changing the font for [questions] doesn't work"). Replies and Composer were applying (checked live: face loaded, CSS names it, it renders). Questions and Reasoning only named `data-t3x-slot` marks from the native bridge archive patch, which T3's nightly updates had removed, and the open question card above the composer was never covered. Their rules now also name T3's own markup (the collapsible with `data-pending-user-input-toggle`, the saved-answer list, the reasoning text box), so updates no longer silently switch them off. The card header, option buttons and shortcuts stay native, as the area has always said.

- **6 Nov — keep title policy in the keeper for now.** Andy chose “Keep all three in keeper (Recommended)” after Astra and Grok compared the native Thread title instructions setting. It appends to generated-title prompts, leaving the conflicting base rule, and does not reach child title formatters or agent orchestration instructions. Keep rule/fit/titleGuide enabled on this install; leave the native field unset. Keeper v14 follows the runtime/delegate bundle split, validates the shared minimum-width constant, and reclaims server indentation with parser/token checks when comments cannot hold the fitter.

- **7 Nov — popups move out of the way (option A of three in a mock, "Drag + small card").** Andy: "allow me to move the popups, because they always block the window and therefore the part of the screen whose font I'm trying to change. or otherwise move the popups out of the way". Every popup drags by its top bar (⠿) and reopens where it was left (spots measured from the nearest window edges, kept in settings); Home on ⠿ or a double-click on the bar puts it back. The Fonts window stays modal but loses the dark wash; its Small card button turns it into the docked card, placed clear of that area's text, and the pick flow uses the same placement, keeping clear of the text just picked whenever there's room. Rejected: drag only (the 980 px window stays in the way) and a move-aside button. GPT-6-Astra's pre-OK found that the first placement search (a 24 px grid scored by total overlap) could miss an exact gap and cover the picked text; candidates now line up with every text edge, touching or 12 px away, and the picked text is kept clear first. Astra's final gate then found that rounding to whole pixels could still clip a half-pixel gap, so positions stay unrounded. Own switch, `popMove`.

- **12 Nov — nothing about the sidebar goes upstream.** On 9 Nov Andy asked for a short presentation of the title rules, with three notes for upstream, to send to T3 Code's maintainers. On 12 Nov T3 Code's contributing guide was rewritten to say it takes bug fixes from outside the team and not features ([pingdotgg/t3code#34797](https://github.com/pingdotgg/t3code/pull/34797): "We are explicitly NOT INTERESTED in new feature addition PRs from people outside of said team"; new features and UI overhauls are on the list it closes automatically), and the README was redone the same day ([#35170](https://github.com/pingdotgg/t3code/pull/35170): "We have limited review capacity. Small, focused fixes are the most likely to be merged. Features need an approved discussion first."). Theo's post announcing it, 12 Nov 2026: "Decided to celebrate by rewriting the contribution guidelines. Previous one was basically an LLM-written placeholder. This is...much more me :)", with a screenshot of the new guide's opening lines ([x.com/theo/status/2120821825433469311](https://x.com/theo/status/2120821825433469311)). Andy's decision that day: send nothing upstream about the side panel, and wrap up. So no post, message, issue, discussion or pull request goes to T3 Code about sidebar titles, wrapping or these add-ons; they stay a personal setup in this repo. The presentation page (`docs/sidebar-titles.md` with ten screenshots) was built but is not published: it sits on the local branch `sidebar-titles-page`, unpushed. If this is ever revisited, upstream's published routes are [Ideas discussions](https://github.com/pingdotgg/t3code/discussions/categories/ideas) for feature requests and issues for bugs, and a bug fix is the only outside pull request it takes.

- **13 Nov — geminiQuota follows the probe instead of being retired.** Nightly `0.1.10-nightly.20261113.4643` moved T3's Antigravity limits probe from the runtime bundle into the server bundle, so the unit stopped matching ("found 0 times") although nothing was wrong: the build sends `2.24.0` itself and T3's saved readings held both Gemini windows. The unit now looks in both server bundles and treats any version from `2.24.0` up as T3's own (left alone), so it no longer breaks when T3 moves the code or raises the version. It still rewrites the known-bad `1.0.0` in the runtime bundle of older builds; `1.0.0` in the server bundle (no build has had that) is reported as a failure, not patched. Kept over removing the unit because the repo is installable by others, who may run older builds. Keeper v15.

- **12–13 Nov — Fable's own weekly limit sits inside Claude's usage item** (Andy: "for the usage, please add another indicator/mechanism for fable usage to the claude section"). A consensus team (Claude Opus 5.5, a Claude Fable 5.2 seat, GPT-6.1-Sol, GPT-6-Astra, Grok 4.7 and Gemini) compared options on mock boards over four rounds and agreed on one text: a thin twin bar under the week's bar in every Claude glyph, Fable's number in the label, a tick and a warning colour at the stop the user's own rules set, a Fable row and a thin line in the detail, and the chip naming Fable only when it is the tightest limit. Andy confirmed it on 12 Nov ("Yes, build it"). Measuring the build at the app's real font (500 11 px) then turned up four cases the text didn't cover: two limits showing the same number; a one-line row too wide for "week · Fable"; a two-line row too wide for all three numbers; and the week and Fable both low in one-line mode. The team agreed on one answer for all four after four more rounds (a tie goes to the broader limit; Fable alone or today's line; one healthy number gives way at a time; the week's group first, two lines at most), and Andy confirmed it on 13 Nov. A Fable limit at zero never shows Claude as blocked and leaves the chip's comparison. Built by Grok 4.7 and the lead; four review rounds by Sol (tests and edge cases), Astra (final gate), Opus and the Fable seat, all four approving the final tree. Lesson kept: measure candidate labels at the app's real font before drawing the first board. Not built, recorded as follow-ups: when the service falls back to `lab-usage` for a whole lab, a per-model reading only T3 has is dropped (predates this change); a second per-model limit gets no full row in the detail; in the two-line wrap the copied text has no separator; the week and 5-hour readings refresh the detail's signature at one decimal, not at the shown whole number; "low" is decided on exact values, so a week at 15.3% shows "15%" and is not low; in one-line mode with a low week, a 5-hour window that is only ahead of its clock joins the week's line.
- **13 Nov — Claude's item with no 5-hour window** (Andy: "claude got rid of the 5-hour window, so please update the side-panel usage code accordingly"). Claude's reading now lists the week and Fable's week only. An audit found the add-ons already drew a lab with no short window correctly, because Codex and Grok never had one: no tank, no `5h` number, and a used-up week reads `0% left` with its refill time. One output was wrong and is fixed: the detail's legend named a 5-hour tank even when no lab on screen has one, and now carries that sentence only while a tank is drawn. Nothing was removed, so a reading that lists a 5-hour window (Gemini, Claude AG, or Claude's again) is drawn as before. Nothing else about how Claude's item looks or reads was changed. `test/claude-no-short.test.mjs` pins today's reading shape.

- **13 Nov — the keeper's installer keeps the Node binary it already uses** (Andy: "Yes, do it"). `install.sh` took whichever `node` came first on `PATH`. Run from an agent's shell on 6 Nov and again on 13 Nov, that was a version manager's binary, so the reinstall moved the background job off Homebrew's `node`, the one with App Management, and macOS blocked its next write until a second install with `T3X_NODE` put it back. An update now reads the existing install's `node-path` first and keeps that binary when it is still there and passes the version probe; `T3X_NODE` still wins, a first install is unchanged, and a recorded binary that is gone gets a warning and the old discovery. Only the keeper's installer: the add-ons service does not need App Management.
- **13 Nov — "Your fonts" rows: fixed places over compactness** (Andy: "why is 'use for similar' in a different location for this one? and make it easier to demarcate the different font sections. and also add a little Default size indicator that I can click to go to/from it. don't muddy the look or make it overwhelming"; then "make the font size go up to 200x not just 150x"; he confirmed the team's design with "Yes, build it"). Three fixed lines per font, a hairline between fonts, the action pinned top right; about 145 px taller for five fonts. The Default control's slot is always as wide as its widest label, so rows wrap alike and a click never moves anything. The name stops growing at 150% so − and + stay under the pointer. The size Default leaves is session memory, not a setting, so a row can return to a plain "Default".
